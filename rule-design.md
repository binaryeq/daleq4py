# Rule Design

The old main table is `metadata`, change this to `content`.

## `Content` Predicate

### Columns 

1. `id: symbol` - generated unique id. For the EBD, this is generated by the extraction (e.g. using a counter). For the IDB, this is inferred to encode the derivations. 
2. `file: symbol` - the file name (no path info)
3. `path: symbol` - the path name, relative to the root of the archive (wheel)
4. `key: symbol` - a property key
5. `value: symbol` - a property value

### Explicit vs Synthetic Properties

For metadata files (notably `METADATA` and `RECORD`), facts are created representing key-value pairs in those files. Those are explicit keys. 

For all files, including resources, `.py` sources, and metadata files that are not in key-value format, facts are created for the following two synthetic keys:

1. `@sha256` -- the value is the `sha256` hash of the file
2. `@norm/sha256`-- the value is the `sha256` hash of the file after it has been normalised as follows: 
   1. line breaks are normalised to `\n`
   2. for `.py` files, comments are removed
   3. for `.py` files, formatting is standardised
4. `@src-exists` -- the value if `true` or `false`, indicating whether a source file with this path and name exists in the underlying source repository
5. `@src-exists-moved` -- the value if `true` or `false`, indicating whether a source file with this name exists in the underlying source repository (but is perhaps in a different path)
6. `@src/sha256`: hash of the corresponding source file (even if it is in another folder)
7. `@src/norm/sha256`: hash of the corresponding source file normalised (even if it is in another folder)

## `Package` Predicate

This is an auxiliary predicate.

### Columns 

1. `id: symbol` - generated unique id.
2. `key: symbol` - a property key
3. `value: symbol` - a property value


### Keys and Values

1. `name` key - the value is the name of the wheel
2. `distinfo` key -- the value is the `*.dis-info` folder name containing metadata
